## 事件概述

OpenAI News 在 2026 年 11 月 24 日发布了一篇案例报道，介绍两位业余天文学家如何借助 Codex 和 AI 工具 Astra，在 NASA 开普勒（Kepler）与 TESS 的公开望远镜数据中寻找系外行星候选信号。

两位参与者背景不同：Kevin Bond 是 OpenAI 的工程师，因热爱夜空摄影而接触天文学；Ethan Byrd 是邮件基础设施创业公司 Primitive 的创始人，长期对天文感兴趣。Bond 使用 Codex 搜索了约 10 万颗开普勒恒星的观测数据；Byrd 在尝试多个 AI 模型后选择 Astra，分析了约 1900 万颗恒星的 TESS 数据。

两人的搜索都找到了潜在候选信号，但需要强调：这些结果目前只是“候选”，尚未被确认为行星。Bond 将结果交给 SETI 研究所的天文学家独立复核，对方在开普勒数据中独立找到了其中两个相同信号；Byrd 将一个最强候选提交给 TESS 任务团队，等待进一步分析，另有两个候选待提交。原文没有说明这些候选最终能否被确认，确认过程可能需要数月甚至数年。

## 关键技术点

**1. 凌星法与光变曲线**

文章回顾了系外行星探测中最常见的方法之一：凌星法。当行星从恒星前方经过时，会遮住极少量星光，在恒星亮度随时间变化的光变曲线中形成一个“凹陷”。如果凹陷以固定周期重复出现，就可能是行星轨道造成的。搜索的本质，是在大量恒星光变曲线中识别微弱、周期性、可重复的凹陷。

**2. 用已知行星做“阳性对照”**

Bond 的搜索程序在开普勒公开数据中标记了 200 多个信号，其中 10 个来自此前已确认的行星。找到这些已知行星，让他对程序识别目标信号的能力更有信心。这一步在方法上很关键：它不是直接用 AI 宣布新发现，而是先用已知阳性样本检验搜索流程的召回能力。

**3. 多 Agent 分工：扫描与复核**

Bond 使用 Codex 比较已发表的搜索方法，将它们组合成搜索程序，并测试代码修改是否改善搜索效果。原文描述了一个 AI agent 扫描光变曲线寻找有希望的信号，另一个 agent 对第一个 agent 标记出的候选做更详细检查。这种“初筛 + 复核”的分工，是 Agent 工作流中较自然的模式。

**4. 从方法调研到软件构建**

Byrd 使用 Astra 设计了两类搜索：一类广泛寻找系外行星候选，另一类聚焦恒星宜居带。他还让 Astra 审查已发表方法、构建搜索软件，并对有希望的信号做初步检查。原文未说明 Astra 的具体模型版本、产品形态或是否开源，也未说明其内部 Agent 架构。

**5. 候选信号与后续验证**

Bond 的两个重点候选分别是：

- KIC 5689121：一颗温度较低、约为太阳一半大小的恒星，位于天琴座，搜索发现每 13.8 天出现一次亮度下降；如果由行星造成，遮挡光量暗示其直径约为地球的 2.4 倍。
- KIC 6691030：一颗较暗的北天恒星，搜索发现每 4.8 天出现一次亮度下降，与小于海王星大小的行星相符。

SETI 研究所天文学家独立搜索后找到了这两个相同信号。Byrd 的第一轮搜索则产生 49 个候选，其中一个已提交 TESS 团队等待进一步分析。

文章也强调，恒星变暗并不必然意味着行星存在。双星互掩、望远镜温度变化等都可能造成类似信号。确认行星通常需要统计论证、更多观测，甚至径向速度等不同方法的交叉验证，并经过同行评审发表。

## 对数据科学或 AI Agent 落地的意义

这篇报道的价值不在于“AI 又发现了几颗行星”，而在于展示了一条可复用的 AI Agent 落地路径：**领域问题定义 → 方法检索与代码生成 → 批量数据处理 → 候选初筛 → 二次复核 → 人类专家独立验证**。

对数据科学团队而言，有几个直接启示：

第一，Agent 更适合做“研究助理”和“实验执行器”，而不是最终裁判。Bond 和 Byrd 的 AI 流程输出的是候选列表，最终判断仍交给天文观测、统计检验和同行评审。这种“AI 扩大候选面、人类负责确认”的分工，比让模型直接给出结论更可靠。

第二，评估设计比模型选择更重要。Bond 用已确认行星检验搜索程序，相当于在真实数据中设置了阳性对照。对于风控、运维、生物信息等场景，同样可以先用已知事件检验 Agent 流程的召回率和假阳性率，再讨论自动化程度。

第三，Agent 的多步协作需要可审计的中间产物。原文提到一个 agent 扫描、另一个 agent 复核，也提到用 Codex 比较方法、组合程序、测试代码改动。落到工程上，这意味着需要保留候选列表、筛选参数、代码版本和复核记录。原文未说明这些产物是否公开，但可追溯性显然是科学场景的基本要求。

第四，公共数据与 AI 工具降低了公民科学的参与门槛。NASA 的 Exoplanet Watch 等项目允许没有望远镜的人参与光变曲线分析。AI 工具进一步把“写搜索程序、跑批量数据、做初步检查”的门槛降下来，让更多具备领域兴趣但非职业研究者的人可以参与。

## 我的技术点评

这篇案例最值得肯定的是验证闭环，而不是工具本身。Bond 没有停在“AI 标记了 200 多个信号”，而是检查其中是否包含已知行星，并请 SETI 研究所独立复核；Byrd 则把最强候选提交给 TESS 团队。这种设计承认了 AI 输出的不确定性，也把“候选生成”和“科学确认”明确分开。

从 Agent 工程角度看，Bond 的“一个 agent 扫描、另一个 agent 复核”是一个朴素但有效的编排模式。它对应到企业场景，就是“召回模型 + 精排/复核模型”的分层结构。真正难点不在让 Agent 写代码，而在定义什么叫“有希望”：阈值怎么设、周期性怎么检验、仪器系统误差怎么排除、候选
