## 事件概述

据 MakeUseOf 报道（作者 Brady Snyder，2026 年 10 月 18 日发布），Google 已于 2025 年 10 月正式终止对三代 Nest Learning Thermostat 的支持，这些设备如今只能作为普通"哑"恒温器使用。该文随后在 Hacker News 首页出现（22 points，7 条评论），讨论热度不高，但话题本身触及了一个长期被忽视的问题：**依赖云端的消费级硬件，寿命到底由谁决定。**

涉及的三款设备分别是：

- 2011 年发布的第一代 Nest Learning Thermostat
- 2012 年发布的第二代 Nest Learning Thermostat
- 2014 年发布的欧洲版第二代 Nest Learning Thermostat

Google 在社区公告中表示，这三款设备均已获得超过十年的支持，为了"全力投入最新一代 Nest 恒温器的先进功能"，公司将停止对它们的支持。三款机型的生命周期终点定在 2025 年 10 月，**自 2025 年 10 月 25 日起，任何依赖云服务或 Google Home / Nest 连接的功能全部停止工作。**

## 关键技术点

### 1. 被切断的是"云闭环"，不是设备本身

根据 Google 官方支持文档，这三代设备失去的核心能力包括：

- 在 Nest 或 Home App 中查看恒温器状态
- 远程控制设备
- 接收通知
- 通过手机或平板修改设置

由此连带失效的还有：第三方语音助手连接、与 Nest Protect 配件的联动、Home/Away Assist、多设备 Eco Mode、紧急关断等。这些功能的共同点是，它们都依赖 Google 服务器完成状态同步与决策。

而**不依赖云端的部分仍然可用**：手动设定温度、切换制冷模式、创建自定义日程——但只能在恒温器本机上操作。设备没有被彻底"变砖"，只是智能部分被剥离。

### 2. 固件刷写 + 自托管是恢复路径

一个名为 **No Longer Evil** 的开源项目（开发者 Cody Kociemba）恢复了这些设备的远程控制与面板管理能力。原文描述的路径是：

- 向恒温器刷入新固件，注册免费账号，使用 Web 面板；
- 或者不使用项目方服务器，改为自托管；
- 项目提供 Home Assistant 插件，可将已被官方放弃的恒温器接入自建智能家居服务器；
- 也可以自行搭建 No Longer Evil 服务器，指定自定义 IP 和端口。

原文称，通过该项目可以继续使用远程控制、日程安排和自动离家（auto-away）功能。**至于固件如何逆向、通信协议如何实现、安全模型如何设计，原文未说明。**

### 3. 未受影响的机型

第三代 Nest Learning Thermostat、Nest Thermostat E、Nest Thermostat 以及第四代 Nest Learning Thermostat 目前不受影响。但原文也明确指出：Google 已经立下了先例——Nest 恒温器的联网功能并不保证永久可用。

Google 在停服前曾提前通知用户，并向受影响用户提供升级折扣额度。

## 对数据科学或 AI Agent 落地的意义

这篇报道表面上是一则消费电子售后新闻，但对做 AI Agent 和数据系统的人有几点直接映射：

**第一，云端 API 是 Agent 工具链的单点依赖。** 一个 LLM Agent 的能力边界，往往不取决于模型本身，而取决于它能调用哪些工具。当某个工具背后的服务方单方面下线接口，Agent 的能力会在某个日期突然塌陷——这和三代 Nest 在 2025 年 10 月 25 日"一夜之间失去核心功能"是同一个结构。设计 Agent 时，工具层需要有明确的弃用契约和降级路径，而不是默认接口永续存在。

**第二，设备侧可写固件意味着边缘执行层可被接管。** No Longer Evil 的价值不只是"救活旧设备"，而是证明了当本地硬件具备可刷写能力时，云端撤离并不等于功能终结。对 Agent 系统而言，这对应的是把关键执行逻辑下沉到可控环境（本地推理、本地规则引擎、自托管服务），而不是全部押注在托管 API 上。

**第三，Home Assistant 这类本地中枢正在成为 Agent 的物理世界入口。** 原文提到该项目提供 Home Assistant 插件，这实际上是把一个被厂商放弃的设备重新纳入本地自动化体系。如果未来家庭 Agent 要在真实环境中执行动作，本地中枢的稳定性与数据主权，会比云端助手的"聪明程度"更基础。

**第四，遥测与数据所有权问题被顺带暴露。** 停服之后，这些恒温器的运行数据不再上传 Google。原文未说明 No Longer Evil 是否会收集用户数据，这一点在自托管场景下需要使用者自行核实。

## 我的技术点评

十年支持在消费电子行业确实不算短，但用"十年"去衡量一个恒温器并不合适。恒温器是安装在墙上的建材级设备，物理寿命普遍在十五到二十年以上，用户的心理预期是"用到坏为止"。用软件服务的生命周期去截断硬件的生命周期，本质上是把厂商的迭代节奏强加给了用户。

更值得警惕的是功能剥离的方式。这些设备并非因为硬件损坏而退役，而是因为云端连接被关闭。用户付费购买的"智能"部分，实际上是租用的。这一点在购买时并没有以足够清晰的方式告知。

No Longer Evil 是一个有价值的补救，但它也暴露了开源社区在替厂商收拾残局：项目由个人开发者维护，长期可持续性、固件安全性、账号体系的可信度，原文均未说明。对普通用户而言，"刷固件"仍然是一道不低的使用门槛——尽管原文称该项目面向"各种技能水平的 DIY 用户"。

对做 AI Agent 和数据的团队来说，可迁移的经验是明确的：**在架构设计阶段就要回答"云端消失后还剩什么"**。至少应保留一条不依赖外部服务的本机最小可用路径，并把工具接口的弃用策略写进契约，而不是等到停服公告发出再去补救。智能可以上云，但可用性不能只存在于云上。
