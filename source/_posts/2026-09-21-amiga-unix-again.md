## 事件概述

Hacker News 首页最近出现了一个名为 **Amiga Unix, Again** 的项目，域名是 [amigaux.org](https://amigaux.org/)。它做的事情可以用一句话概括：**把 Commodore 的 Unix 重新捡起来，跑到今天的硬件上。**

背景是这样的。Amiga Unix（简称 **Amix**）是 Commodore 基于 System V Release 4 做的 Unix 系统，1990–1992 年间随 A2500UX 和 A3000UX 出货，然后就停在那里了。此后三十多年，它基本只存在于收藏家和模拟器爱好者的硬盘镜像里。

amigaux.org 是一个**非官方社区项目**，目标是把 Amix 重新激活：

- 支持 68040 和 68060 机器，以及今天的加速卡硬件；
- 引入现代工具链；
- 做一个包管理器；
- 为那些"从来没有过驱动"的扩展卡写驱动。

项目由 **asokero、isoriano1968 和 jusii** 三人在公开环境下推进，所有过程都记录在一份名为 **grimoire** 的文档仓库里。原文没有说明项目的启动时间、资金来源或团队规模。

值得注意的是项目页面上的一段自述：**部分工作是用生成式 AI 参与的**——模型直接读二进制形式的老内核（因为源码不可得），并编写驱动和文档；人负责定方向、审查每一次改动、在真机上测试。原文特别强调，真机测试的结果很直接，"要么能启动，要么不能"。其他部分则按传统方式完成。grimoire 会同时记录这两类工作，并带有**置信度标记**，以区分哪些是已验证的、哪些还只是猜测。

## 关键技术点

### 1. 内核移植：68040 / 68060

目前可用的状态包括：

- **Amix 2.1 在真实 68060 上运行**，有或没有 FPU 都可以；
- **MMU 是必需的**；
- 内核仓库为 `asokero/amix-040-060-port`；
- 配套的 `asokero/amix-unix-boot` 提供补丁，让 Markus Wild 的 `unix_boot` 能在 68040/68060 上加载 Amix 内核。

### 2. 硬件驱动

- **Z3660 加速卡**：原生的 SCSI 和以太网驱动，已在真机验证；
- **A4091 / A4092**：Zorro III SCSI 驱动，以及一个可自动检测的内核；
- 相关仓库包括 `jusii/amix-z3660scsi`、`jusii/amix-z3660net`、`jusii/Z3660-amix`、`jusii/amix-a4091` 等。

### 3. 安装流程

安装介质支持两种路径：

- **真机**：从软盘 + CD-ROM 启动；
- **模拟器**：软盘镜像 + ISO 镜像。

安装过程支持**交互式**或**无人值守**两种模式。原文举了一个例子：在真实 68060 上安装时，流程会依次确认 keymap、磁盘、分区大小、软件包集合，然后在动手之前**先展示它将要做什么**。首次启动时系统会给自己命名、设置时钟、写入 hosts 文件（其中包含软件包仓库地址），最后停在登录提示符。原文提到，演示视频里"把漫长的等待剪掉了"。

经典的**磁带安装**方式会在后续补上。

### 4. apkg 包管理器

安装完成后，网络接管一切。`apkg` 可以直接从 `pkg.amigaux.org` 安装软件包。原文给出的示例：

```bash
# apkg update
catalog updated: 39 packages
# apkg install less
downloading extra/less-704.pkg ...
installed less-704
```

首批打包的是现代 GNU 工具：**grep、gzip、less、patch、zlib**，更多 GNU 和 BSD 工具会在构建和测试完成后陆续加入。apkg 具备目录、依赖和升级能力。

### 5. 交叉工具链与桌面

- `isoriano1968/gcc-cross-amix`：Linux 宿主上的 **m68k-cbm-sysv4** 交叉工具链，用于构建上述所有组件；
- 全新安装后会直接进入一个 **OpenLook 桌面**；
- **Quake 可以运行**——不过原文说得很坦白，目前它"更像跑分而不是游戏"。

### 6. 进行中与下一步

**进行中**：

- Z3660 的 RTG 图形（兼容 ZZ9000），已在模拟器下跑通，真机是下一步；
- 加速卡固件中的以太网吞吐优化；
- X11R6.3 和 Mesa 作为软件包（来自社区移植），之后是更广的用户空间；
- 只读 CD 文件系统（ODFileSystem 移植）；
- 安装介质打磨：修复路径、防护措施、磁带版本。

**下一步**：

- 在机器上跑原生的现代 gcc；
- 真机加速卡上的 RTG；
- 打包好的 X11R6.3 / Mesa 栈；
- 固件以太网修复；
- 正式发布：软件包、源码、说明文档和手册。

## 对数据科学或 AI Agent 落地的意义

这个项目表面上和机器学习无关，但它提供了一个非常具体的 **AI Agent 在"无源码、无文档、不可调试"的遗留系统上工作**的样本。

**第一，它示范了一种可审计的人机分工。** 原文的描述是：模型读二进制内核、写驱动和笔记；人定方向、审查每一次改动、在真机上验证。这是一个**闭环的验证结构**——不是让模型自由发挥，而是把它的输出强制送进一个物理执行环境（真机能不能启动）里做二值判定。对于任何想在生产环境中使用 Agent 的团队，这个结构比"模型能力"本身更值得抄。

**第二，置信度标记是一种低成本的对齐手段。** grimoire 同时记录 AI 参与和人工完成的工作，并标注置信度，让人能区分"已验证"和"仍是猜测"。这其实是把模型的不确定性显式暴露给下游读者，避免幻觉被后续文档继承、放大。

**第三，任务形态是天然的 Agent 场景。** 二进制逆向、为陌生硬件接口写驱动、维护一份持续更新的知识库——这些任务有明确的成功判据（编译通过、真机启动、包能装上），适合做成"生成—测试—修正"的多轮循环。相比之下，很多企业里的数据科学 Agent 恰恰缺这种可自动化的判据。

当然，原文未说明模型的具体类型、调用方式、prompt 策略、验证覆盖率，也没有给出 AI 参与部分与传统方式部分的量化对比。**这些关键细节全部缺失**，所以这个案例更适合当作方法论启发，而不是性能证据。

## 我的技术点评

这是一个"看起来很小众、但结构上很有意思"的项目。

让我真正注意到的不是 Amix 本身，而是那句"models reading the old kernels in binary, as no source is available"。这类工作在过去是极少数逆向工程专家用几年时间磨出来的手艺活，现在可以被拆解成大量"读一段反汇编、猜一个语义、写一段驱动、跑一次真机"的小循环。**真机测试这个环节在这里起到了关键作用**：它把模型的生成能力锚定在一个无法被语言说服的现实约束上——硬件不 care 你的解释有多合理。

第二点让我欣赏的是**文档里带置信度标记**。绝大多数 AI 辅助的工程项目，要么完全不标注哪些是 AI 写的，要么过度自信地把生成内容直接写进文档。把"已验证 / 仍是猜测"写成文档的一部分，是一种很务实的工程纪律。

不过保留意见也有两条。

其一，**项目页面的宣传语和实际交付之间还有距离**。目前真正"Working today"的清单里，驱动主要集中在 Z3660 和 A4091/A4092 这几款卡上，X11R6.3/Mesa、RTG 真机、原生 gcc 都还在进行中或待办。原文自己说得清楚，正式发布（软件包、源码、说明、手册）是"Then"的事。所以现在更准确的定位是**一个高质量的技术预览**，不是可以拿来日常用的发行版。

其二，**"AI 参与"这个说法本身缺少可核验的细节**。这并不一定是问题——很多工程细节不适合公开——但如果你打算把这个项目当作引入 AI Agent 做遗留系统改造的论据，它目前提供的只是方向性的证据，不是可复现的方法论。原文未说明模型、工具链、验证流程的具体设计。

即便如此，amigaux.org 依然值得放进收藏夹。它展示了一个可能性：**当源码消失、文档散佚、原始工程师都已退休，生成式 AI 加上真机验证循环，也许能让一些被时间封存的系统重新跑起来。** 至于这条路能走多远，只能等那些"Then"的部分真正落地。
