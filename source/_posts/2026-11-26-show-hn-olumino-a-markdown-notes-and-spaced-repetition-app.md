## 事件概述

Hacker News 首页出现了一个名为 **Olumino** 的 Show HN 项目（[olumino.app](https://olumino.app)），作者自述是一名计算机科学专业的学生，利用业余时间开发。项目灵感来自 Mochi 和 Anki：作者认为 Anki 的界面陈旧、上手混乱，而 Mochi 简洁但极简到功能不够，于是想做一个“两者的结合体”。此外还加入了面向日语学习者的闪卡支持，包括假名读音标注。

该 HN 帖子的数据为 4 分、4 条评论（发布时间 2026-11-26 03:33:06，来源 Hacker News: Front Page）。

产品定位很明确：**写笔记 → 把笔记变成闪卡 → 按你对卡片的掌握程度安排复习时间**。官网原话是 “Write notes, turn them into flashcards, and review each card on a schedule based on how well you know it.”

## 关键技术点

### 1. 用 FSRS-7 做调度

这是整个产品最“工程化”的部分。官网明确说明：Olumino 用 **FSRS-7** 为每张卡片排期，并称其为“在数百万条真实复习记录上训练过的开放方法”。用户每回答一次（Forgot / Recalled / Instant 三档），卡片下次出现的时间就会被重新计算：越熟的卡片间隔越长，越容易忘的卡片回来得越快。

官网给出的学术脉络有两条：

- **Ebbinghaus (1885)**《Über das Gedächtnis》：人会在几天内忘掉所学的大部分内容，而每一次复习都会让记忆维持得更久。
- **Ye, Su, Cao (2022), KDD '22**：*A Stochastic Shortest Path Algorithm for Optimizing Spaced Repetition Scheduling*，即把间隔重复的排期问题建模为随机最短路径问题来优化。

这两条引用也恰好解释了 FSRS 一类算法的基本思路：把“记忆强度”当成可估计的隐状态，把复习时机当成一个带成本的决策问题，目标是用尽量少的复习次数维持尽量高的留存率。

### 2. 三档反馈与“月亮”可视化

交互上只做三个动作：向左滑 = 忘了，向右滑 = 记住了，向上滑 = 瞬间想起。对应的反馈隐喻是一个从**新月到满月**的月相：

- 新月：还没学过的卡片；
- 学习阶段：刚学会的卡片会在一两天内回来；
- 逐渐变强：每次记住，下次间隔从几天拉到几周、几个月；
- 满月：间隔三周后仍能想起，说明可能能保持一个月以上，但仍会偶尔复习。

官网特别强调一句：**月相只有在你隔了一段时间后仍然记得，才会增长**。这个细节很关键——它避免了把“刚看完立刻答对”也算作掌握程度提升。

### 3. Revisit：针对“反复翻车”的卡片

如果一张卡片在**一次会话中忘掉三次**，就会被放进 Revisit 单独练；连续答对两次后恢复正常调度。这是对 FSRS 主调度器的一个补丁式设计，把“明显超纲或编码质量差的卡片”从主流程里隔离出来，避免它们反复污染复习队列。

### 4. 笔记与卡片的双向流动

- 可以在写笔记的过程中生成建议卡片；但官网明确写了：**不会自动添加任何内容，除非你自己添加**。
- 支持从 Anki 导入卡组，**连同复习历史一起导入**；也可以把任意卡组导出为 Anki、电子表格、Quizlet、Markdown 或可打印的纸质卡片。
- 设置里有一键导出：把所有卡组、卡片、笔记和图片打包成单个文件，可在任意设备重新打开。

### 5. 部署与数据存放

纯浏览器运行，电脑 / 平板 / 手机都能用，手机可以添加到主屏当 App 用，无需安装。数据**优先落在本地设备**；登录后会在账号里保留一份副本用于多设备同步，且只有自己可见。跨设备同步属于 Olumino Plus，$8/月（卡组、卡片、笔记和刷卡本身免费）。

关于隐私，官网有一段值得注意的披露：**当“卡片建议”开启时，你正在写的那段文字会被发送出去**以生成建议，可以在设置中关闭。

### 6. 日语支持与教师模式

- 16 种语言和口音的朗读；日语额外提供汉字上的假名读音、词典、书写练习。
- 教师可以创建班级并分享链接，学生拿到卡组，教师能看到**本周谁学了多少**以及**全班反复忘的是哪些卡**；对师生免费。

## 对数据科学或 AI Agent 落地的意义

需要先说明一点：**原文并未提及任何 AI Agent、大模型或多智能体相关能力**。官网里与“AI 生成”最接近的只有“卡片建议”这一功能，且原文未说明其具体技术实现。所以这里的意义属于类比与迁移，而非对产品本身的描述。

从数据科学视角看，这个项目有三个可迁移的点：

1. **把用户体验问题形式化为一个可优化的决策问题。** 间隔重复看起来是“学习工具”，本质是“在不确定状态下做序贯决策”——每一次复习都有成本，遗忘也有成本，FSRS 用随机最短路径的思路去逼近最优策略。任何需要“何时再打扰用户一次”的产品（推送、提醒、巡检、客服回访）都是同一类问题。

2. **三档反馈是极低成本的标注接口。** Forgot / Recalled / Instant 只用一个滑动动作就采集到了“记忆强度 + 反应速度”的粗糙标签，长期累积后就是训练调度模型的燃料。对 Agent 系统而言，这提示了一件事：**把人类的隐式反馈压缩成 2～3 个互斥选项，比让用户填表更容易拿到高密度数据。**

3. **明确的“异常隔离”机制。** Revisit 本质上是一个人工规则兜底：模型排不准的卡片，就别让模型继续排。在 Agent 落地中同样是常见做法——把低置信度或高频失败的 case 从自动流程里摘出来单独处理，比指望模型自己纠正更可靠。

## 我的技术点评

**做得对的地方：** 选择 FSRS-7 而不是自研一个“看着像间隔重复”的启发式算法，是一个成熟的决定。间隔重复领域已经有开源实现和公开论文支撑（官网直接列出了 KDD '22 那篇），复用成熟调度器能把精力集中在笔记编辑、卡片生成和交互上，这对一个业余时间开发的个人项目来说是合理的取舍。导入 Anki 时**连复习历史一起导入**这个细节尤其加分——没有历史的卡片对 FSRS 来说是冷启动，两者体验完全不同。导出格式覆盖 Anki / 表格 / Quizlet / Markdown / 打印，等于承认了“用户随时可能离开”，反而更容易让人敢进来。

**需要观察的地方：**

- **月相可视化的表达成本。** 用月相代替数字化的“下次复习时间”，审美上是加分项，但用户心里那个“我到底什么时候会再见到这张卡”的确定性被削弱了。原文未说明界面上是否同时显示具体的下次复习时间。
- **同步要收费、免费版只有本地数据**，意味着多设备用户的真实转化点被放在了同步上。这是个清晰的商业模式，但也意味着免费用户体验的完整性依赖单一设备。
- **“卡片建议”会上传正在写的段落**这件事，官网写得很坦诚，但它与“数据优先存在本地”的叙事存在一定张力。对教育场景（尤其是未成年学生）来说，这段说明值得做得更显眼，而不是放在 FAQ 里。
- 作者是学生、业余时间开发，**服务的长期可用性和数据可迁移性**是用户最该关心的问题——好在单文件全量导出这一条基本覆盖了这个风险。
