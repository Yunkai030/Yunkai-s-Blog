## 事件概述

2026 年 11 月 23 日，OpenAI 与思科（Cisco）联合发布 Shirudo——一个面向 Linux 的开源运行时，目标是帮助团队在补丁发布和部署的窗口期内保护正在运行的 Linux 系统。原文指出，从测试到部署补丁有时需要数天甚至数周，而在此期间保护服务相当困难：漏洞利用与合法请求可能依赖同一个 Linux 操作，若直接屏蔽该操作，可能导致服务下线。

Shirudo 名称取自日语“盾”（shield）。它让安全团队可以验证一种名为 shield（盾牌）的临时防护措施：既能阻断暴露漏洞的行为，又能放行合法请求。操作者批准后，盾牌可在服务持续运行的情况下部署。

在受控测试中，由 OpenAI Codex 生成的盾牌成功阻断了一次针对运行中 Elasticsearch 服务的 Java4Shell 漏洞利用尝试，全程无需重启服务。OpenAI 总裁兼联合创始人 Greg Brockman 表示，与思科在 Shirudo 上的紧密合作，是为了帮助团队在构建和推出修复方案的同时保护必须持续运行的系统，并强调在开放环境中构建这些工具的意义——当一个团队找到更好的防护方式时，其他团队不必从零开始。

## 关键技术点

- **eBPF 作为底座**：Shirudo 使用 eBPF——一种允许小型程序在操作系统特定位置运行的 Linux 技术——来观察可疑活动，并对运行中的系统施加针对性的安全防护。
- **四项核心能力**（原文列举）：
  1. **实时防护**：eBPF 盾牌可以阻断存在漏洞的代码路径而无需重启系统；安全团队可在正式强制执行前，观察拟议盾牌对应用的影响。
  2. **机器速度的防御**：OpenAI 与思科正设计让智能体（agents）具备可编程控制能力，以调查漏洞、开发针对性盾牌，并针对漏洞利用和真实工作负载验证其有效性；最终部署什么仍由安全团队决定。
  3. **可信部署**：盾牌在加载前经过密码学签名与验证；Linux 的 eBPF 验证器会按其安全规则检查 eBPF 程序，同时内核安全控制限制未经授权的更改。
  4. **硬件背书验证**：Shirudo 使用可信平台模块（TPM）支持对防护加载或移除的可验证记录，运维人员可据此检查系统是否满足其安全要求。
- **Java4Shell 演示**：团队使用 Codex 生成了一道盾牌，为 Java 的 Base64 解码器增加输入检查，并将其直接挂载到运行中的 Elasticsearch 进程上。在尝试利用该漏洞时，盾牌拒绝了恶意输入，攻击被阻断，而 Elasticsearch 继续运行。
- **开源许可**：Shirudo 以 BSD 2-Clause 许可开源，其 BPF 程序采用 BSD 与 GPL 双重许可。

## 对数据科学或 AI Agent 落地的意义

原文的长期愿景直接指向 AI Agent 在安全运维中的落地：让防御者与 AI 智能体能够快速识别受影响的系统、验证防护措施，并部署 eBPF 盾牌以阻断漏洞利用而不干扰工作负载。应用应当只以所需的最小权限运行，并由自动生成与维护的策略治理。

原文还提到，OpenAI 与思科希望将前沿 AI 与安全、基础设施研究结合，用于发现漏洞并针对真实攻击测试防御。此外，项目目标包括让经过测试的盾牌与漏洞披露一同发布，使运维人员在准备永久补丁期间有办法评估和部署临时防护。

对于数据科学与 AI 工程团队而言，这意味着 AI Agent 的应用场景正从“内容生成 / 代码辅助”延伸到“运行时安全控制”。Shirudo 的“智能体提出防护方案 + 人工审批 + 密码学与内核机制保障执行”这一链路，为 AI Agent 进入生产环境的敏感操作提供了一个可参考的治理范式。需要说明的是，原文未说明具体的 Agent 实现细节、模型版本或推理链路，也未给出性能开销数据。
